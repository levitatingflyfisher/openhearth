## Take the code as current-state, not gospel

Every line of source and every comment here was written by an AI assistant. Treat it as
**an accurate record of what currently exists, offered with gratitude and a grain of
salt** — not as a specification and not as guaranteed-correct. A comment claiming an
invariant is a *hypothesis to verify*, not a proof. If a comment and the tests disagree,
the tests win; if the tests and reality disagree, reality wins.

## What this is (and its status)

A close-friend **presence signal** — the porch-light metaphor. Turn the porch light *On*; friends in
your groups see the light is on; they reach you on a channel they already use. **Porch is
pre-release:** the relay, the client crypto and the app's screens are built and tested on
a development machine, but the app has **never run on a phone**, the widget and
background refresh are not built, and **no relay is deployed** (the app ships a `.invalid`
placeholder URL). Check HONEST-STATUS before you document or build on anything.

## Non-negotiables (breaking one is a regression, not a feature)

- **Presence, not communication.** No in-app chat, no calling, no scrollable feed, no
  read receipts — ever. ([ADR-0001](docs/adr/0001-presence-not-communication.md))
- **The relay stays blind.** Everything that leaves the device travels as an **encrypted
  blob** to an unguessable address. No plaintext presence, no accounts, no BaaS.
  Access to the relay is by capability (knowing an id), not by login; the mailbox drain is
  the only signed request. ([ADR-0002](docs/adr/0002-dumb-e2e-relay-not-baas.md),
  [ADR-0006](docs/adr/0006-capability-channels-no-session-plane.md))
- **No PII, no accounts.** Identity is 16 locally generated bytes (the 12 words) from which
  the keys are derived. ([ADR-0003](docs/adr/0003-ed25519-identity-no-accounts.md))
- **Ephemeral presence.** Presence slots expire on a TTL and are structurally gone after —
  never a soft-delete flag. ([ADR-0005](docs/adr/0005-ttl-ephemeral-presence.md))
- **No custom crypto.** libsodium via `sodium` / `sodium_libs` in the app (pinned exact);
  Go `crypto/ed25519` and `golang.org/x/crypto` in the relay.
- **Zero logging in the relay.** relayd prints nothing while it serves: no access logs, no
  startup line, `net/http`'s error log discarded. Output is only requested help/version on
  stdout and invocation or startup errors on stderr, before serving. `privacy_test.go` greps
  the API package; the integration test asserts zero output bytes.
- **TDD, always.** Reproduce → failing test → fix → green → commit. Every bugfix ships with
  a regression test.
- **Atomic commits, one concern each.** Commit messages state the *why*. **No AI
  attribution or co-author trailer lines** — deliberate project policy.
- **Never commit** `docs/superpowers/` or local agent-config files. This repo ships
  `AGENTS.md`.

## How to work here — two build stories

Full commands: [docs/how-to/build-and-run.md](docs/how-to/build-and-run.md).

### The relay (`relay/`)

```bash
cd relay
go vet ./...
go test ./...            # the Redis conformance leg skips visibly without REDIS_URL
go run ./cmd/relayd -h
```

- Go 1.25+. Dependencies: the standard library and `golang.org/x/crypto`; Redis is spoken
  through the package's own RESP client (`internal/store/resp.go`). No web framework —
  `net/http` with method-pattern routing.
- A new endpoint must return bare status codes, reject unknown JSON fields, cap its blob
  size and sit behind a rate-limit bucket — and must never log.

### The app (`app/`)

```bash
cd app
flutter pub get
flutter analyze
flutter test test/<layer>/<file>_test.dart   # one file at a time on a small machine
```

- Layers are enforced: `lib/domain/` is Flutter-free and `lib/data/` imports no Flutter
  (`test/*/purity_test.dart`). Platform plugins are bound only in `bootstrap.dart` or a
  named adapter file.
- Screen tests use `test/presentation/support/ui_world.dart`: a `FakeRelay`, in-memory
  stores and a controllable clock, overriding the same providers bootstrap does. Its
  default relay URL is a configured one; set `relayUrl = defaultRelayUrl` to test the
  shipped no-relay state.
- Goldens live in `test/presentation/goldens/` (a11y sweep). Never regenerate them to make
  a failing test pass without knowing why the pixels moved.
  They are tagged `golden`: CI compares pixels only locally and still runs their overflow
  checks (`.github/workflows/ci.yml`).
- `test/fleet_conformance_test.dart` holds porch to the fleet standards
  (`oh_fleet_conformance`); every check left off is listed there with its reason. porch
  has no router, so `test/presentation/screen_doors_test.dart` stands in for C9: every
  screen must be constructed somewhere outside its own file.
- Riverpod 3 rules. Retry is off: give every new async provider
  `retry: noAutoRetry`, and keep `porchProviderScope` as the root (bootstrap and
  `pumpPorch` use it). A failed read is shown, never read as empty: `AsyncValue.value`
  is null on a failure, so check `hasError` before `.value` wherever null means
  "nothing yet" (the root gate does; `read_failure_test.dart` pins it). No
  keystore read before `runApp` may stop the app: a read launch needs goes in
  `launchReadsProvider`, which the gate watches first, and bootstrap wires
  from it with `launchWiring`. Onboarding's `_run` catches every failure,
  Errors too. A provider's
  own `ref.listen` stops once nothing watches the provider; Porch has none today.
  Home's `ref.watch` pauses under a pushed route and catches up when shown again.
- The theme is `openhearth_design` (`OhTheme` with porch's amber as the accent). Use its
  widgets (`OhPage`, `OhErrorState`, `showOhConfirm`) rather than local copies.

## When you're unsure

Prefer *not* collecting to collecting. Prefer a failing test to a plausible fix. Prefer
matching the surrounding code to introducing a new pattern. On anything that touches
identity, encryption, logging, or what leaves the device, prefer asking (or leaving a
`TODO` with the open question) to guessing. Read [docs/adr/](docs/adr/) before reopening
a decision.
